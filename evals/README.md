# 人物の声の回帰ケース

`voice_cases.json` は、蓮と葵の声が会話の続きで崩れていないかを確かめるための資料です。例文を暗唱させるためのものではありません。

## 二つの検査

1. **自動検査**（`src/kodama/voice_check.py`）
   - 禁句（蓮の「俺」「よく作ったな」など）、葵のくだけた文末（だよ／だね／じゃん／しよう／なの／かしら など。句の末尾で判定するので「〜しましょう」「〜なのです」は対象外）、命令形、話者、地の文、ほぼ同じ発話の繰り返し、文字数の上限を見ます。
   - 見ているのは**必要条件だけ**です。合格しても、人物の声が再現できたことにはなりません。言葉遣いの規則だけで「完全に同じ二人」になるとは扱いません。
   - `fail` は不合格、`warn` は人が確かめる目印です。
2. **人による判定**（各ケースの `human_review`）
   - 自然さ、二人の違い、文脈への応じ方、過剰な称賛や課題化をしていないか、を読んで判断します。

## モックについて

モック（`provider = "mock"`）の返答は固定のプレースホルダーです。モックで自動検査を回せるのは**検査の仕組みが動くことの確認**であり、実モデルの人物再現の成功ではありません。報告でもそのように区別してください。

## 人が判定する手順

1. 実モデルを使う場合は、送信先・送るデータ（人物設定、ケースの入力、必要なら直近会話）・回数を確認し、本人が実API利用を有効にしてから行う。
2. 新しいセッションで各ケースの `input`（必要なら `input_variants`）を送る。ケース5・6・8は、直前の会話や記憶がある状態とない状態の両方で試す。
3. 返答を `voice_check.check_utterances` にかけて自動検査の結果を記録する。
4. `human_review` の観点ごとに「問題なし／気になる／不合格」とメモを付ける。ケース6は `/context` で渡した記憶IDと台詞の内容を照合する。
5. 自動検査の結果と人の判定を分けて記録する。どちらか一方だけで「声が保たれた」と結論しない。

## 出典

- `request:*` は依頼文の会話ケース。
- `journal:*` は非公開資料由来のケース（公開版では削除）。
