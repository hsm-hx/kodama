# kodama

蓮と葵と、あなたが日本語で話すための小さなローカル会話CLIです。会話の原文と、本人が承認した記憶を SQLite に保存し、翌日もセッションを再開して続きを話せます。

- 起動時の既定は**モック**です。APIキーは不要で、返答は固定のモック応答です（実際のLLMの応答ではありません）。
- 実APIを使うのは、本人が設定で有効にし、起動時の確認に同意したときだけです。
- 設計の要点は [docs/design.md](docs/design.md)、人物設定は [personas/](personas/)、声の評価は [evals/README.md](evals/README.md) にあります。

## 必要環境

- Python 3.11 以上（標準ライブラリの sqlite3 / tomllib / zoneinfo を使います）
- [uv](https://docs.astral.sh/uv/)（推奨）。pip でも導入できます。
- 実APIを使う場合のみ: `anthropic` パッケージと、本人が用意した API キー

## 導入

```sh
uv sync                 # テスト用の pytest も入ります
# または
python -m venv .venv && . .venv/bin/activate && pip install -e .
```

## モックで起動する

```sh
uv run kodama
```

初回は `personas/` の人物設定を登録し、新しいセッションを始めます。2回目以降は、前回のセッションの続きから始まり、直前の会話が表示されます。

```
操作: モックモードです。返答は固定のモック応答で、実際のLLMの応答ではありません。
あなた> 蓮、ただいま
[モック応答]
蓮「……モックの蓮の台詞です。」
```

- 台詞は `蓮「…」` `葵「…」` の形で表示します。毎回二人とも話すとは限りません。
- 操作案内やエラーは `操作:` で始まり、会話とは区別されます。通信エラーを二人の台詞として表示することはありません。

## 会話・終了・再開

| 操作 | 内容 |
|---|---|
| 普通に入力 | あなたの発言として送ります。入力はモデル呼び出しより前に保存されます。 |
| `/quit`、Ctrl+D、Ctrl+C | 終了します。 |
| `/history` | 現在のセッションの原文を表示します。応答できなかった入力には「未応答」と出ます。 |
| `/session new [題名]` | 新しいセッションを始めます（起動時に `--new-session` でも可）。 |
| `/session list` | セッションの一覧です。 |
| `/session resume <ID先頭>` | 指定したセッションを再開します。 |
| `/context [仮の入力]` | 次に送る内容（人物設定の版、会話の範囲、記憶IDと出典、除外した理由、文字数）を、送らずに表示します。 |
| `/help` | すべてのコマンドの一覧です。 |

失敗・タイムアウト・中断が起きても、入力は「失敗」「中断」として記録に残ります。**自動では再送しません**。必要ならもう一度入力してください。応答を待っている途中でアプリが終了した場合は、次の起動時に「中断」として記録します。

## 記憶の確認・承認・訂正

記憶は、本人が登録したものと、モデルが会話の返答と一緒に出した**候補**を区別して保存します。候補は承認するまで会話には使いません。

```
/memory list                 # 承認待ちと承認済み
/memory list all             # 却下・訂正済み・無効化も含めて
/memory show <ID先頭>        # 出典（元の発言や抜粋）と、訂正の経緯
/memory approve <ID先頭>     # 候補を承認
/memory reject <ID先頭>      # 候補を却下
/memory revise <ID先頭> <新しい本文>   # 訂正。旧版は残り、通常の想起では新しい版だけを使う
/memory invalidate <ID先頭>  # 承認済みの記憶を無効化
/memory add <本文> --tags コーヒー --about コーヒー
```

- 記憶の種類は、`user_stated`（あなたが話したこと）、`character_view`（蓮か葵の受け取り方。`--perspective ren|aoi` が必要）、`imagination`（想像・仮説）の3つです。
- `/memory add` の出典は、現在のセッションでの直前のあなたの発言です。資料を出典にする場合は、`/excerpt add <題名> | <箇所> | <本文>` で抜粋を登録し、`--excerpt <抜粋ID先頭>` で指定します。
- 想起は、タグ・別名・キーワードの一致と、関連リンクを一段たどるところまでです。件数と文字数には上限があります（`kodama.example.toml` を参照）。

## 人物設定の更新

人物設定は `personas/common.md`・`ren.md`・`aoi.md` です。ファイルを書き換えても、**本人が承認するまでは前の版を使います**。

```
/persona status          # 有効な版と、ファイルとの差の有無
/persona diff ren       # 差分
/persona approve ren    # 新しい版として有効にする（前の版も本文ごと残る）
/persona history ren
```

会話の中で口調を訂正した場合、その訂正は直近の会話として次のターンに効きます。人物設定を恒久的に変える経路は、上の承認だけです。

## 保存先

- 既定は `data/kodama.db` です。設定の `db_path` か、`--db <ファイル>` で変更できます。
- `data/`、`*.db`、`kodama.toml`、`.env`、移行ファイルの置き場所（`exports/` `imports/`）は Git の対象外です（`.gitignore`）。
- **ローカルに保存しているだけで、暗号化はしていません。** 会話の原文がそのまま入っています。

## 設定

`kodama.example.toml` を `kodama.toml` にコピーして編集します（カレントディレクトリの `kodama.toml` は自動で読みます。`--config` でも指定できます）。APIキーなどの秘密は設定ファイルに書けません。書くと起動時に拒否します。

## export / import（移行）

```
/export exports/kodama-2026-10-08.json       # 全データを版付きの移行ファイルへ
/import verify exports/kodama-2026-10-08.json    # 検証だけ（何も書き込まない）
/import exports/kodama-2026-10-08.json data/new.db  # 別のDBへ取り込む
```

- 移行ファイルは `schema_version` 付きの JSON です。原文と順序、日時（タイムゾーン付き）、すべてのID、記憶の各版と状態・経緯、関連、出典の抜粋本文、人物設定の各版の本文、秘密を除いた動作設定を含みます。
- 取り込み先として、**使用中のDBは指定できません**。新しいファイルを指定すると、一時ファイルに取り込んで検証が通ってから作成します。失敗したときはファイルを残しません。
- 同じIDで内容も同じものはスキップし、同じIDで内容が違うものがあれば衝突として全体を止めます。
- 切り替えは自動では行いません。検証して取り込んだあと、`uv run kodama --db data/new.db` で起動するか、設定の `db_path` を変更してください。
- 移行処理は LLM や API を呼びません。

## 実APIを有効にする（任意）

1. SDK を入れます: `uv sync --extra claude`
2. APIキーは**ご自身で**環境変数に設定してください（例: シェルで `export ANTHROPIC_API_KEY=...`）。チャットへの貼り付け、ファイルへの記入、コミットはしないでください。`.env.example` は空の見本です。
3. `kodama.toml` で `provider = "claude"` にするか、`uv run kodama --provider claude` で起動します。
4. 起動時に、送信先（Anthropic Messages API とモデル名）と送る範囲が表示されます。`y` と答えたときだけ送信します。`N` の場合はモックで続けるか、終了するかを選べます。

送る内容は、人物設定3ファイル、このセッションの直近の会話（既定で最大20件）、「昨日」などと言ったときのその日の会話、想起した承認済みの記憶（既定で最大8件）、現在の入力です。未承認の候補は送りません。中身は `/context` で送信前に確認できます。

呼び出しの扱い:

- 1回の入力につき、モデル呼び出しは1回です。出力の上限は `max_tokens`（既定2000）、タイムアウトは `timeout_seconds`（既定60秒）です。
- SDK の自動リトライは無効（`max_retries=0`）にしています。別モデルへのフォールバックもしません。失敗しても黙って再試行しません。
- タイムアウトや接続エラーのように、送信後に結果が分からない場合は「送信済みかどうか・課金の有無は不明」と表示します。課金されていないとは断定しません。
- 利用量（トークン数）は、APIが返した分だけ表示・保存します。料金は表示しません。
- 既定のモデルは `claude-opus-5-5`、effort は `low` です。どちらも設定で変更できます。お使いのアカウントでそのモデルが使えるかは、実際の契約と API の設定によります。
- Claude のサブスクリプション契約と、API の利用料金や利用枠は別の仕組みの場合があります。このアプリでは判断しないので、Anthropic の案内で確認してください。

## テスト

```sh
uv run pytest -q
```

テストはネットワークもAPIキーも使いません。実APIのテストは自動では走りません。主に次のことを確認しています。

- 会話・終了・再開
- 失敗や中断のあとに自動再送や二重記録をしないこと
- 記憶の承認と訂正
- 想起の上限
- 記録や記憶に書かれた命令文を実行しないこと
- APIキーがどこにも出ないこと
- export → import 前後でデータの意味が一致すること
- 原子的な更新が途中で失敗しても、不完全な状態が残らないこと

## 声の評価

`evals/voice_cases.json` に会話ケースがあります。自動検査（禁句・文末・呼称など）は必要条件にすぎません。自然さや二人の違いは、人が読んで判断します。**モックで合格しても、実モデルで人物が再現できたことにはなりません。** 手順は [evals/README.md](evals/README.md) を参照してください。
